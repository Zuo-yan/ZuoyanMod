# ZuoyanMod 新 Boss「湮灭君主」+ 程序化 Boss 遗迹「湮灭王座」实现计划

## 背景结论（已核实）
- 「超平坦世界」= 模组自带维度 `zuoyanmod:realm`（生成器 `zuoyanmod:realm_flat`，地表 y≈135）。
- 已从 MC 26.3 源码/官方 wiki 核实：平坦维度只有 `structure_overrides` 里列出的结构集才会生成，当前 `dimension/realm.json` 写的是 `[]`（什么都不生成）。因此只需把新结构集加进该字段即可在超平坦世界启用，无需改生成器代码。
- 模组已有可复用基础：`LandCheckedJigsawStructure`（陆地检查）、`RickEntity` + `RickRenderer`（26.3 人形实体/RenderState 渲染范式）、`DescriptionBlockItem`（物品描述 tooltip）、`tags/entity_type/bosses.json`（Boss 标签）。
- 工具链：JDK 25 / NeoForge 26.3，构建需 cd 到嵌套目录 `ZuoyanMod/ZuoyanMod`。

## 一、Boss 设计：湮灭君主（void_monarch）
### 战斗数值（写死，参照系：Rick 攻击 42、凋灵血 300、末影龙血 200）
| 属性 | 湮灭君主 | 湮灭侍卫（void_guard） |
|---|---|---|
| 最大生命 | **2048** | 120 |
| 近战攻击 | **100**（狂暴后 **120**） | 30 |
| 护甲 / 韧性 | 20 / 12 | 10 / 4 |
| 击退抗性 | 1.0（免击退） | 0.6 |
| 移速 | 0.30（狂暴 0.36） | 0.28 |
| 索敌范围 | 48 | 32 |
| 弹幕（暗物质投射物） | 每发 **40** | — |
| 沉眠回血 | 每秒 5（未觉醒时） | — |

- **形象**：约 1.6×3.6 格的人形君主，自定义人形模型（加宽肩甲/披风/巨剑），64×64 皮肤贴图（tools/ 纯 Python 脚本程序化生成，与现有 gen_*.py 同范式）。
- **觉醒机制（与两参考模组的差异点）**：结构生成时以「沉眠」状态坐在王座上（不攻击、缓慢回血、免击退）；玩家进入王座 6 格触发觉醒——字幕标题 + 音效 + Boss 血条出现，血条名称「湮灭君主」。
- **三阶段 AI**：
  1. 挥砍阶段：大范围近战横扫；
  2. 血量 <60%（≈1229）：召唤 2~3 名「湮灭侍卫」+ 暗物质弹幕（40/发）；
  3. 血量 <30%（≈614）：狂暴——移速 0.36、攻击 120、弹幕加密、攻速提升。
- **Boss 条**：`ServerBossEvent`（紫红色，NOTCH 段样式），首次在本模组引入，`startSeenByPlayer/stopSeenByPlayer/tick` 标准范式。
- **掉落**：首个实体战利品表 `loot_table/entities/void_monarch.json`——必掉新武器「湮灭君王之刃」（monarch_blade：攻击 35、对 bosses 标签目标 +50% 伤害）+ 紫金锭/暗物质粒子若干。君主注册进 `tags/entity_type/bosses.json`（侍卫不加，保持克隆服务对侍卫正常）。

## 二、建筑设计：湮灭王座（程序化生成，中型遗迹 ~56×56）
- **新 Structure 子类** `MonarchCitadelStructure`（注册为 `zuoyanmod:monarch_citadel`）：复用 LandCheckedJigsawStructure 的「地表非液体」检查逻辑，然后用自己的 piece 拼装器生成——不走 jigsaw。
- **布局**（每次按种子随机变化）：
  - 中央沉降式王座大殿（石砖+深板岩砖+紫金块立柱，王座平台在正中）；
  - 两侧对称塔楼（随机高度 12~20，内有螺旋阶梯 + 宝箱）；
  - 前庭断墙残垣（随机缺口的墙体）、入口大门；
  - 殿内 2~4 个宝箱（新战利品表 `chests/ruined_monarch_citadel.json`：紫金装备线、奇点核心碎片级材料）+ 若干侍卫游荡。
- **接入超平坦低概率生成**：
  - `structure_set`：random_spread `spacing=384, separation=320`（平均 2000+ 格一座，低概率）；
  - `tags/worldgen/biome/has_structure/monarch_citadel.json` 值为 `["zuoyanmod:realm"]`；
  - `dimension/realm.json` 的 `structure_overrides` 从 `[]` 改为 `["zuoyanmod:monarch_citadel"]`。

## 三、文件清单
**Java（`org.gwfx.zuoyanmod` 下）**：`worldgen/MonarchCitadelStructure`、`worldgen/MonarchCitadelPieces`（piece 类+拼装器）、`WorldgenRegistry`（注册新 StructureType）、`entity/VoidMonarchEntity`、`entity/VoidGuardEntity`、`EntityRegistry`（两个实体+属性）、`client/VoidMonarchRenderer`、`client/VoidGuardRenderer`、`client/ZuoyanModelLayers`（模型层）、`Zuoyanmod.ClientModEvents`（注册渲染器）、`item/ItemRegistry`（monarch_blade、两个刷怪蛋、加入创造模式标签页）。
**数据 JSON**：structure、structure_set、biome tag、realm.json 的 structure_overrides、实体/箱子两张战利品表、bosses 标签、击杀君主成就 advancement。
**资源**：`textures/entity/void_monarch.png`、`void_guard.png`、`textures/item/monarch_blade.png`、刷怪蛋贴图（按 rick_spawn_egg 现有范式）、`lang/zh_cn.json` + `en_us.json` 全部新键。

## 五、验证
1. `cd ZuoyanMod/ZuoyanMod && ./gradlew build`（Windows 构建锁问题按记忆中的方法处理）。
2. `./gradlew runServer` 建临时世界，`/execute in zuoyanmod:realm run locate structure zuoyanmod:monarch_citadel` 验证结构在超平坦维度生成（参考 tools/verify_worldgen.sh、structure_locate.py 的既有流程）。
3. `runClient` 手动验证：传送到遗迹→觉醒演出→三阶段战斗（2048 血量曲线）→掉落物与宝箱战利品→门框 tooltip 显示。

## 风险与备选
- 26.3 的 `ServerBossEvent`/`StructurePiece` 签名以本地源码为准，编译期即暴露，风险低。
- 若 `structure_overrides` 在 26.3 行为与预期不符（备选）：改在 `RealmFlatChunkGenerator` 里接管结构放置，代码量小。
- 程序化建筑若首轮观感不佳，piece 拼装器可继续调参（塔高/缺口率/装饰密度）而不动框架。
