# 绝对零度 · 超流体暗物质 · 设计文档（GDD）

状态：**已实现（第三版 · 移除凝聚链 + 范围扩大 + 改为冰系合成）** · 2026-09-22
前置文档：`void_resonance_pump.md`（暗物质粒子的产出侧）
环境：NeoForge 26.3.0.3-beta / Minecraft 1.26.3 · modid `zuoyanmod`

## 1. Fun Hypothesis

> 这个道具好玩的核心是：**你用 15 秒的时间停止，换一片属于你的致命量子流体——但你自己也站在里面。**

它不是"点一下变强"的道具。它要求玩家**先把暗物质丢在地上**，再赌自己能在 15 秒内
离开那片即将变成致命环境的区域。**布置 → 释放 → 撤离**是它的全部手感，
失误的代价是当场死在自己的技能里。

## 2. Design Pillars

| # | 支柱 | 过审用法 |
|---|---|---|
| P1 | 相变即玩法 | 暗物质的三态（粒子/固相/超流体）各有独立获取路径，相变不是换皮 |
| P2 | 布置先于释放 | 只有**掉落物形态**参与相变，逼玩家在现场动手，不能背包里一键转换 |
| P3 | 施术者是参照系 | 时停不作用于自己——这既是设定，也是唯一的生路 |
| P4 | 熵不白送 | 超流体的致命属性完全沿用原设定，不做任何"因为是技能产物所以无害"的削弱 |

## 3. 暗物质的三相阶梯（转化机制总览）

```
末影珍珠 / 龙息 / 紫颂果
        ↓ 投入（虚空共振泵 · 末地悬空）
暗物质粒子 ──(9:1，3×3 有序合成)──→ 暗物质（固相）
                                        ↓ 绝对零度 / 玻色-爱因斯坦凝聚
                              超流体暗物质（凝聚态，零粘度）
                                        ├─ 环境：就地液池（致命，PvP 陷阱 / 封路）
                                        └─ 搬运：用桶取回「超流体暗物质」物品
```

**物理叙事（这是整套命名的依据）**：玻色-爱因斯坦凝聚与超流体本就是同一件事——玻色子冷却到临界温度
以下全部坍缩到同一量子基态，宏观表现即**零粘度的超流体**（液氦的超流性正是 BEC 的宏观证据）。
所以「绝对零度」→「玻色-爱因斯坦凝聚」→「超流体暗物质」不是三个随便凑的名词，而是一条自洽的相变链。

## 4. 暗物质 → 超流体暗物质：具体规则

> 这是本节的核心，回答"怎么转化"。

| 项 | 规格 |
|---|---|
| 转化入口 | **只有一途**：使用「绝对零度」释放 BEC。没有工作台配方，也不是泵的第二种产物 |
| 前提形态 | 必须是**掉落物**（`ItemEntity`）。背包/箱子/地上的暗物质**方块**都不参与——P2 |
| 转化范围 | 与冻结范围**同一个场**：施术者所在方块为中心、半径 6 格的 **13×13×13** |
| 触发时机 | **释放瞬间一次性完成**，不是 15 秒内持续转化 |
| 转化率 | **1 个暗物质 → 1 格超流体暗物质流体源** |
| 单次上限 | **128 格**。超出部分**原样留在地上**（不吞东西），原因见 §7 |
| 落点规则 | 以物品所在格为中心由近及远：先同一水平层铺开（半径 0→6 的方环），再向下一层，最后向上。多层堆叠会摊成一片液池而不是叠在一格里 |
| 落点不足 | 找不到可放位置时**不消耗**该物品（原样留在地上） |
| 不重复投放 | 已经是超流体暗物质的位置会被跳过。流体方块本身 `replaceable`，不排掉它就会出现"物品被吃掉、流体没变多"的吞货 bug |
| 产物属性 | **完全沿用**原液态暗物质：强制下沉 / 每秒 4 点真伤 / 剥夺增益 / 半秒碎 2 点装备耐久 / 每 5 秒剥一级附魔 / 急速窒息 / 黑暗失明。**仅紫金神装全套免疫** |
| 扩散特性 | 流体是刻意调"粘稠"的：`slopeFindDistance(2)` + `levelDecreasePerBlock(2)` + `tickRate(20)` + `canConvertToSource(false)` → 横向最多渗出 3 格左右，且**无法形成无限源** |
| 可逆性 | 可以用桶舀回（1 桶 = 1 格源），所以液化是"状态转换 + 道具成本"，不是净消耗 |
| 真正的 sink | **只有绝对零度的耐久**（3 次一次性消耗）。流体不蒸发（见 §9.2），回收也不是净消耗，所以固相暗物质在"液化"这条路上其实没有稳定消耗——除非玩家愿意扔掉它 |

**为什么转化入口是技能而不是配方**：做成配方就变成"在背包里点两下"，玩家与那片流体的位置关系就消失了，
而"你必须站在自己造的液池中心"正是这个道具全部的张力来源。

**移除记录**：第一版曾有一个"凝聚合成链"效果（把场内材料一次性串成终点物品）。用户判定其描述多余、
与核心玩法无关，**已完整移除**（`crafting/CoalescenceRecipes.java` 已删除）。圣天胸甲本来就有正规的
锻造台配方 `shengtian_chestplate_smithing.json`，因此这次移除**没有让任何物品失去产出路径**。

## 5. 绝对零度（道具规格）

**该道具只有两个效果，别的一概不做。**

| 项 | 规格 |
|---|---|
| 效果 ① | **冻结范围内所有实体，持续 15 秒（300 tick）** |
| 效果 ② | **把范围内的暗物质掉落物转化为超流体暗物质流体** |
| 获取 | **工作台合成**：4×蓝冰 + 4×冰 + 1×雪块（见 §9.1）；创造栏也保留 |
| 稀有度 | EPIC |
| 耐久 | **3 次**，用尽物品销毁，不可修复 |
| 触发 | 右键（主手/副手） |
| 冷却 | 无独立冷却；但**场上已有未消散的凝聚场时拒绝释放**（防止连点白烧耐久） |
| 范围 | 施术者所在方块为中心、半径 6 格 → **13×13×13**（与转化范围完全同一） |
| 冻结范围排除 | **施术者本人**（见 §5.2） |
| 音效 | `GLASS_BREAK`(0.45 pitch) + `PLAYER_HURT_FREEZE` |
| 视觉 | 起手 40 枚雪片 + 30 枚白灰扩散；场存续期间每 4 tick 补雪片 |

### 5.1 冻结的具体行为（诚实版）

| 目标 | 处理 | 冻结程度 |
|---|---|---|
| 生物（僵尸/骷髅/苦力怕…） | 速度归零 + 关闭 AI（`Mob.setNoAi`）+ 清空攻击目标 + 6 级缓慢 | **近似完全冻结**：不移动、不攻击、不寻路、不攻击建筑 |
| 其他玩家 | 速度归零 + 6 级缓慢（移动速度≈0） | **定身，但能反击**：走不动，却仍可攻击、挖掘、使用物品、喝药、丢末影珍珠 |
| 掉落物 | 速度归零 | **悬停在空中**（这是"时间停止"最直观的一眼证据） |
| 方块 | 不处理 | **不冻结**：流体照流、作物照长、红石照跑 |

**为什么玩家只是定身**：玩家的移动是**客户端权威**的——服务端 `setDeltaMovement` 对玩家基本无效，
真正把玩家钉住的是 6 级缓慢（客户端自己也跑这个减速，所以不会发出快速移动包）。
要让玩家变成"真·冻结"，必须额外拦截攻击/挖掘/物品使用事件，见 §9.1。

**已知可绕过**：喝下**牛奶桶**能清掉缓慢，被冻的玩家可以直接走出场。要不要堵这个口子见 §9.1。

**AI 的还原**：关掉的 AI 在场消散（或实体被移除）后**还原为原值**，不是无脑置 false——
避免把本来就是"无 AI"的生物（刷怪笼产物等）打开。用 `UUID → 原始值` 备份表 + 引用表实现，
引用只保留到下一个 tick，不长期持有实体。

### 5.2 为什么施术者不被冻结（必读）

超流体暗物质按原设定是**碰到就融化**级别的致命环境。而效果 ② 会在施术者脚下造出这片环境。
如果施术者也进入时停，他会**被冻在自己的液池中心 15 秒**——技能变成"用一次死一次"，道具直接不可用。

所以设定上：**施术者是这个场的参照系**。冻结的是别人的时间，你自己的时间照常流逝。
这 15 秒就是**撤离窗口**。这条不是平衡补丁，是"冻结只冻别人"这个设定的必然推论，
也是效果 ① 与效果 ② 能同时存在的前提。

### 5.3 自伤风险是刻意保留的

用户决策：**超流体属性按原设定，不做任何削弱**（不改成惰性基态、不给施术者免疫）。
后果：施术者必须自己走开，否则会死于自己的技能。这是 P1/P4 要的手感——
道具的强度与它的自杀风险成正比，玩家对"半径 6 格有多大、15 秒能跑多远"的估算就是 skill expression。

## 6. 边界情况

| 情况 | 行为 |
|---|---|
| 场内没有暗物质 | 照常时停，不相变（技能仍然有效——它是一个时停控场道具） |
| 暗物质是**方块**形态（已放置） | 不转化，只有掉落物形态才有效 |
| 暗物质**粒子**（`DarkMatterParticleItem`） | 不转化——它是固相的前体，见 §9.2 |
| 一叠 200 个暗物质 | 只转化 128 个，剩余 72 个原样留在地上 |
| 落点被实心方块占满 | 该暗物质不消耗、留在原地（不吃玩家东西） |
| 落点上已有超流体 | 跳过该点，不消耗物品（防吞货） |
| 施术者自己站在落点上 | **会被自己造的流体吞掉**——刻意的，见 §5.3 |
| 场内有其他玩家 | 一起被定身；被钉在液池里的人会持续被侵蚀（PvP 的核心用法） |
| 被冻的玩家喝牛奶 | 清掉缓慢 → 走出场。已知绕过，见 §9.1 |
| 场内有原本无 AI 的生物 | 场消散后还原为"无 AI"，不会被错误激活 |
| 释放后立刻退出游戏 | 场不持久化（内存态），重进即消失；不会残留冻结的生物 AI 状态 |
| 场跨区块 | 只处理已加载区块内的实体（MC 常规行为） |
| 一次放了 3 次 | 每次都要等上一个场消散；3 次用完物品销毁 |

### 26.3 API 备忘（都从反编译源码确认，勿凭记忆写）

| 需要 | 正确写法 |
|---|---|
| 减速效果常量 | `MobEffects.SLOWNESS`（**不是** `MOVEMENT_SLOWDOWN`） |
| 移除实体 | `entity.remove(Entity.RemovalReason.DISCARDED)`——**`discard()` 在 26.3 已不存在** |
| 范围查询 | `level.getEntitiesOfClass(ItemEntity.class, aabb)`（`EntityGetter` 的 default 方法） |
| 13×13×13 的 AABB | `new AABB(blockPos).inflate(RADIUS)`（`AABB(BlockPos)` 构造存在） |
| 放置流体 | `level.setBlockAndUpdate(pos, BlockRegistry.DARK_MATTER_BLOCK.get().defaultBlockState())`——`Fluid.createLegacyBlock` 是 **protected**，调不到 |
| 判断"这格已经是我们的流体" | `state.is(BlockRegistry.DARK_MATTER_BLOCK.get())`（流体方块 `.replaceable()`，不能只靠 `canBeReplaced()`) |
| 耐久扣除 | `stack.hurtAndBreak(1, player, hand)`（InteractionHand 重载） |
| 物品耐久属性 | `props.durability(n)` 自带 `stacksTo(1)`，不用重复写 |

### 贴图踩坑（别再犯）

1. **1px 斜臂在 16×16 上呈"虚线感"**，不成形 → 斜臂必须用 2 像素阶梯（像素画里画粗斜线的标准手法）。
2. **六臂雪花放不下描边**：1px 斜臂的四邻全是透明，自动描边会把整条臂吃掉 → 细结构靠明暗对比立形状，不用描边。
3. `(*WHITE if cond else other, 255)` **不是合法解包**，必须先算变量再展开。

## 9. 决策记录与待定问题

### 9.1 ✅ 已解决：绝对零度改由工作台合成（冰 / 浮冰 / 蓝冰 / 雪块）

配方文件：`data/zuoyanmod/recipe/absolute_zero.json`（`minecraft:crafting_shaped`）

```
冰     蓝冰   冰
蓝冰   雪块   蓝冰
冰     蓝冰   冰
```

| 材料 | 数量 | 折算成原版冰 |
|---|---|---|
| `minecraft:blue_ice` | 4 | 4 × 9 浮冰 = 36 浮冰 = **324 冰** |
| `minecraft:ice` | 4 | **4 冰** |
| `minecraft:snow_block` | 1 | —— |
| **合计** | | **约 328 个冰 + 1 个雪块** |

设计意图：中心是"雪块做的冷凝核心"，四周一圈是最冷的**蓝冰**（冰系方块里唯一真正的终局材料），
四角用普通冰补形。全部取自原版寒带生物群系（冰刺之地 / 冰山），不需要任何 mod 专属材料——
即"绝对零度"这个概念本身就能从原版素材推出来。

> 成本偏高是有意的（它是 3 次的时停 + 致命液化入口），但如果你觉得太肝，
> 把 4 个 `blue_ice` 换成 `packed_ice` 即可降到约 40 个冰。**改动只需编辑那一个 json。**

### 9.2 ✅ 已决定：超流体**不蒸发**

用户已明确取消"放置后 5 分钟蒸发、不可回收"的机制。

**说明：这条机制从头到尾都只是一个"建议"，并没有写进代码。**
`void_resonance_pump.md` §9.3 与本文档上一版都只是把它列为"建议做，但需要单独一轮"，
实际实现里流体方块**没有任何定时消失逻辑**——所以本次决策不需要改动任何代码，
它是把"待决定"正式关闭为"不做"。

**被接受的后果（记录在案，避免以后当成 bug）**：
- 超流体暗物质落地即**永久存在**，不回收就永远留在地图上
- PvP 服可以用它做永久封路 / 永久地图疤痕
- 单次释放最多 128 格源、每格再渗出约 3 格 → 一次能造出相当大的一片
- 唯一的"清理"手段仍然只有：用桶舀回（1 桶 = 1 格源）

### 9.3 仍待决策

1. **其他玩家要不要"真·冻结"**。现状：走不动，但能攻击、挖掘、使用物品、喝药。
   真冻结需要额外拦截 `AttackEntityEvent` / `BlockEvent.BreakEvent` / `PlayerInteractEvent` / 物品使用，
   并堵住牛奶桶清缓慢的口子。
   **我的建议是不做**：15 秒内被剥夺全部行动能力且无法反击是"秒杀级"控制，PvP 里极难反制；
   现在的"定身但能反击"已经很强，而且制造了博弈——被冻的人原地反抗，施术者必须撤离。
   如果你要的是纯粹的"时停"幻想，我可以按三档实现：①现状 ②只禁攻击 ③全禁。
2. **时停是否要扩展到方块 tick**：当前不冻方块（技术风险最低）。真·时停（流体不流、作物不长）
   需要 mixin 拦 tick，多人服还有性能与兼容隐患。用户已选择"只冻实体"，此处仅记录代价。
3. **单次 128 格的上限**是否合适：128 格源 × 每格渗出约 3 格 ≈ 视觉上一片不小的池子。
   如果你觉得太狠（或太保守），改 `MAX_CONVERSIONS_PER_CAST` 一个常量即可。
