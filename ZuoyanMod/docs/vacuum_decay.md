## 1. 一句话定位

> **一把 137 伤害、攻速无惩罚、探到 5.73 格的万能锤。攻击只是手段，真正的玩法是"标记 → 引爆 → 聚怪"。**

它不是"更好的剑"。剑解决"打死"的问题，真空衰变解决**"把人/怪搬到一起"**的问题——
黑洞把半径 16 格内的一切拽成一个团，然后 20 点爆炸收尾。这是全场唯一的 AOE 聚怪工具。

## 2. Design Pillars

| # | 支柱 | 过审用法 |
|---|---|---|
| P1 | 先标记，后引爆 | 【分子离解】是引信不是伤害手段，两段式操作逼玩家规划出手顺序 |
| P2 | 自身是奇点 | 全效果都把施术者摘出去：不吃牵引、不吃爆炸，也不被自己的效果反噬 |
| P3 | 一物两用 | 它同时是终局挖掘工具，不该只在战斗里被拿出来 |
| P4 | 复用而非重造 | 【分子离解】直接复用液态暗物质那个同名效果，不新造一个同名 debuff |

### 4.1 附魔适用范围：剑类 + 镐类

需求是"附魔限定为剑类武器和镐子的附魔"。在 26.3，**哪些附魔能上哪件物品完全由标签决定**
（`Item.Properties.enchantable(n)` 只影响附魔台的等级消耗，不决定适用性）。

做法：把自己的物品 id 加进对应的原版 `#minecraft:enchantable/*` 标签，**不动别的物品**。

| 加入的标签 | 因此可用的附魔 |
|---|---|
| `enchantable/melee_weapon` | 击退、抢夺（还会级联出下面两项） |
| `enchantable/sharp_weapon` | 锋利 |
| `enchantable/weapon` | 亡灵杀手、节肢杀手 |
| `enchantable/sweeping` | 横扫之刃 |
| `enchantable/fire_aspect` | 火焰附加 |
| `enchantable/mining` | **效率** |
| `enchantable/mining_loot` | **时运、精准采集** |
| `enchantable/durability` | 耐久、经验修补 |

> ⚠️ **本轮顺带发现一个既有缺陷（我没有擅自改，等你决定）**：
> 项目里已有的 `data/minecraft/tags/item/enchantable/sword.json`（里面放着北冥狂刃与开膛手的手术刀）
> 在 26.3 是一个**死标签**——43 个原版附魔里**没有任何一个**引用 `enchantable/sword`。
> 也就是说那两把武器目前**吃不到任何剑类附魔**。要修的话，把它们的 id 挪进
> `enchantable/melee_weapon` + `enchantable/sweeping` + `enchantable/sharp_weapon` 即可。
> 这会改变既有物品的行为，所以我没有擅自动手。

## 5. 效果① 普朗克解构（万能挖掘）

> **一切方块都能被正确采集，挖掘速度统一 12.0。**

| 项 | 规格 |
|---|---|
| 覆盖范围 | **全部方块**，不区分材质类型（石头/木头/泥土/矿石/蜘蛛网…） |
| 正确掉落 | 任何方块都能掉落（等同"拥有正确的工具"） |
| 挖掘速度 | 统一 **12.0**（比下界合金镐 9.0 快，但没到瞬破）。**刻意不写进 tooltip**——玩家只需要知道"什么都能采"，多给一个裸数字没有信息增量，反而引导他去和原版工具做无意义的数值对比 |
| 耐久消耗 | **0**（无限耐久） |

**为什么叫"普朗克解构"**：普朗克尺度下时空本身失去连续性，物质"是什么材质"这个问题不再成立——
所以它对一切方块一视同仁。它同时也是"真空衰变"这条命名线的自然延伸（都指向时空结构的瓦解）。

**怎么实现的（这是 26.3 的关键技巧）**：挖掘行为由 `DataComponents.TOOL` 组件驱动，
而 `Item` 的三个入口**只是去读那个组件**：

| 入口 | 覆写后返回 |
|---|---|
| `getDestroySpeed(ItemStack, BlockState)` | `12.0F` |
| `isCorrectToolForDrops(ItemStack, BlockState)` | `true` |
| `mineBlock(...)` | `true`（保留覆写只为统计"物品使用次数"，不扣耐久） |

**为什么不挂 TOOL 组件**：TOOL 组件只能表达"一组 `HolderSet` 规则"，
而"所有方块都能采"在注册期**凑不出**这样一个 HolderSet——那时拿不到 registry lookup 去展开
`mineable/pickaxe` 之类的标签。覆写三个入口等价、更短、且天然覆盖全部方块。

## 6. 效果② 负熵灌注

> **手持真空衰变时，自身受到的伤害降低 80%。**

| 项 | 规格 |
|---|---|
| 触发条件 | **手持**（主手或副手），不需要挥动、不需要命中 |
| 作用对象 | 只有自己 |
| 效果 | 最终伤害 × 0.2 |
| 覆盖范围 | 一切伤害来源——近战、远程、摔落、火焰、虚空、饥饿，不做类型豁免 |

**为什么实现在 `LivingDamageEvent.Pre`（护甲结算之后）而不是 `LivingIncomingDamageEvent`（结算之前）**：
后者减 80% 之后还要再吃一遍护甲减免，实际收益会明显超过 80%，和描述不符。
前者拿到的是"护甲 + 抗性算完之后要扣多少血"，乘 0.2 才是字面上的"伤害降低 80%"。

**与其它系统的交互**：这条只减伤，不免疫击退、不免疫状态效果、不免疫被拉进别人的黑洞。

## 7. 效果③ 分子离解

> **攻击敌人时，为敌方附加持续 60 秒的「分子离解」。**

**重要前提：这个效果在本 mod 里已经存在。**
`effect.zuoyanmod.molecular_dissolution` 的中文名就是「分子离解」，是液态暗物质的侵蚀载体
（见 `MolecularDissolutionEffect`）。所以本武器**不是新造一个同名 debuff，而是复用它**——
两个同名效果同时出现在玩家的效果栏里会是纯粹的 bug 观感。

| 项 | 规格 |
|---|---|
| 效果 id | `zuoyanmod:molecular_dissolution`（复用） |
| 中文名 | 分子离解 |
| 持续 | **60 秒**（由武器施加；液态暗物质接触时是每秒续期 4 秒） |
| 伤害 | 每秒 **4 点相位侵蚀真伤**（无视护甲与抗性），60 秒合计 240 点 |
| 附带 | 效果图标 + 粒子（原版效果自带的视觉反馈），**不额外附加致盲**（见 §11.6） |
| 反制① | **全套圣辉套装免疫该侵蚀伤害**（效果仍会挂上，见下） |
| 反制② | **牛奶桶**清掉效果 → 引信一并消失，无法被引爆 |
| 二次作用 | 它是「对称破缺」的**引信**；被引爆时会被拆掉 |

### 7.1 关于"圣辉套装免疫"为什么需要改一行

「全套圣辉套装免疫暗物质侵蚀」是本 mod 的公开承诺，而这条承诺原本只在**踩进液态暗物质**那条路径上生效
（`DarkMatterEventHandler` 在液体里 `return` 掉）。武器直接附加效果会**绕过它**，等于悄悄推翻了承诺。

处理：把"是否穿全套圣辉"抽成 `util/HallowedSet`，让**两条入口共用同一份判定**：

- 液体路径：穿戴者完全不进侵蚀流程（行为不变）
- 效果路径：**伤害被免疫，但效果本身仍然挂在身上**

第二点是刻意的：如果连效果都不挂，圣辉套装就顺带免疫了「对称破缺」的黑洞，一个反制吃掉两个效果。
现在的结果是——**圣辉套装能扛住侵蚀，但照样会被黑洞吸走**。

## 8. 效果④ 对称破缺

> **若攻击目标身上存在「分子离解」，则引爆该效果并产生黑洞。**

| 项 | 规格 |
|---|---|
| 触发 | 近战命中一个**已带**「分子离解」的目标 |
| 引爆 | 立刻移除目标身上的「分子离解」（引信拆掉） |
| 黑洞位置 | 目标身体中心 |
| 聚怪半径 | **16 格**（以黑洞为中心的立方体范围） |
| 牵引对象 | 该范围内**除施术者外**的所有实体（含生物、玩家、掉落物） |
| 牵引强度 | 每 tick 施加加速度，越靠近中心越强（`0.09 + 0.20 × 接近度`），中心 0.9 格为死区防抖动 |
| 黑洞时长 | **5 秒**（100 tick） |
| 坍缩 | 对 **半径 8 格**内的活体各造成 **20 点伤害** |
| 自身豁免 | **不被牵引、不被爆炸伤害** |
| 伤害类型 | `zuoyanmod:vacuum_decay` —— **普通伤害**，正常吃护甲/抗性/保护附魔（不是真伤） |
| 视觉 | 开幕 PORTAL 反向粒子 + 深空音；存续期每 2 tick 补粒子；坍缩 EXPLOSION_EMITTER + 爆炸音 |

**"除自身以外"覆盖了两处**：既不把施术者拽进去，也不在他身上爆。所以施术者可以站在黑洞正中当锚点
——但**别把黑洞开在自己脚边**：爆炸半径 8 格内的一切（除了他自己）都会挨 20 点，队友和宠物一样跑不掉。

**同时存在的黑洞上限 8 个**：纯安全阀。一个黑洞每 tick 要遍历半径 16 格内的全部实体，
十几个叠加是明确的卡顿源；满了会顶掉最老的那个。

## 10. 26.3 API 备忘（都从反编译源码确认，勿凭记忆写）

| 需要 | 正确写法 |
|---|---|
| **万能工具** | 不挂 `DataComponents.TOOL`，改覆写 `Item` 的三个入口：`getDestroySpeed` / `isCorrectToolForDrops` / `mineBlock`。注册期拿不到 registry lookup，凑不出"包含全部 mineable 标签的 HolderSet" |
| **无限耐久** | 注册时**不调 `props.durability(n)`**。`max_damage` 组件缺失 → `ItemStack.isDamageableItem()` 为 false → `hurtAndBreak` 内部短路。因此**也不需要 `repairable()`**，并且 `Weapon(itemDamagePerAttack)` 应写 0 |
| **速度同步（关键）** | 26.3 **没有 `hurtMarked`**。`Entity.push()` 只置 `needsSync`（同步位置），要同步速度必须手动 `entity.syncVelocity = true`，`ServerEntity.sendChanges()` 才会补发 `ClientboundSetEntityMotionPacket`。**漏了这步玩家纹丝不动，只有生物会被吸过来** |
| 伤害事件选型 | 护甲结算**之后**改数值 → `LivingDamageEvent.Pre` + `getNewDamage()/setNewDamage()`；结算**之前** → `LivingIncomingDamageEvent` + `getAmount()/setAmount()` |
| 对实体造成伤害 | `living.hurtServer(serverLevel, damageSource, amount)`——`Entity.hurt(DamageSource, float)` 已标 `@Deprecated` 且是 `final` |
| 自定义伤害来源 | `new DamageSource(Holder<DamageType>, @Nullable Entity direct, @Nullable Entity causing)`；判断类型用 `source.is(ResourceKey<DamageType>)` |
| 拖动实体 | `entity.push(dx, dy, dz)` + `entity.syncVelocity = true`；`entity.isSpectator()` 要手动排除 |
| 音效常量类型 | `GENERIC_EXPLODE` 等是 `Holder.Reference<SoundEvent>` → 传参要 `.value()`；`GLASS_BREAK` / `PORTAL_TRIGGER` / `WARDEN_SONIC_CHARGE` 是裸 `SoundEvent` |
| 判定"是否手持" | 主手 `getMainHandItem()` + 副手 `getOffhandItem()`，不要扫背包 |

## 11. 必须一起讨论的问题

### 11.1 ⚠️ 137 伤害让效果④在普通怪物身上几乎触发不了（最重要）

【对称破缺】要求"目标**已经**带着「分子离解」"，也就是**必须命中第二次**。
但 137 点伤害一击就能秒掉绝大多数生物（僵尸 20、苦力怕 20、末影人 40、铁傀儡 100……）。
**结果是：打小怪永远只看到效果③，看不到黑洞。**

能真正跑完两段式的只有：末影龙 / 凋灵 / 监守者 / 打了 Boss mod 的高血目标，以及**另一个玩家**
（有护甲 + 吸收 + 抗性时能扛住第一下）。

**三个选项：**

| 方案 | 说明 | 代价 |
|---|---|---|
| A. 保持现状 | 黑洞是"打 Boss / 打玩家"的专用手段，小怪不配 | 玩家可能以为效果④坏了（需要靠 tooltip 说明白） |
| B. **标记目标死亡也引爆** | 第一击杀了带引信的目标时，在尸体位置开黑洞 | 偏离字面设定；但"聚怪"这个诉求才真正落地 |
| C. 标记时给目标短暂免死 | 命中时如果目标会被打死，则保留 1 点血 | 手感很怪，且这是"帮敌人保命"，容易挨骂 |

**我的建议是 B**：用户的原话是"从而实现聚怪效果"，而聚怪的对象本来就是成群的**普通怪**，
A 会让这条效果在实际游戏里 99% 的时间不出现。但这属于偏离原描述，所以**没有擅自实现**。

### 11.2 效果③ 的 240 点真伤是不是太重

60 秒 × 每秒 4 点真伤 = **240 点**，无视护甲、无视抗性。
后果：任何被打中一次的玩家，只要**没有牛奶**、**没穿全套圣辉**，就必定在 60 秒内死亡，
且没有任何操作能挽回（跑不掉、抗不了、只能找牛奶）。

这与我复用了同名的既有效果直接相关（见 §7）。选项：
①保持（它就是这个 mod 的力量水平）；②另做一个轻量的「分子离解·标记」，只做引信不带 240 真伤；
③把侵蚀改成"每 5 秒 4 点"（60 秒共 48 点），保留压迫感但不致命。**这题必须你定。**

### 11.3 ✅ 已解决：获取路径

工作台合成（用户指定"四个紫金锭换成超流体暗物质"）：

```
暗物质        超流体暗物质    暗物质
超流体暗物质   圣遗物核心     超流体暗物质
暗物质        超流体暗物质    暗物质
```

= **4 暗物质（四角）+ 4 超流体暗物质（四边）+ 1 圣遗物核心**

- 「超流体暗物质」就是注册 id 为 `dark_matter_bucket` 的那个物品（只改过显示名）。所以**必须先有「绝对零度」**：
  它液化暗物质 → 用桶舀起来 → 才有这个材料。这条链把"锤子 ← 超流体 ← 绝对零度 ← 暗物质 ← 虚空共振泵"串成了一条闭环。
- 4 个桶进配方、**4 个空桶还回来**（注册时加了 `craftRemainder(BUCKET)`，等同原版奶桶）。
- 总计 8 个暗物质（= 72 个暗物质粒子）+ 1 个圣遗物核心，是全局最贵的单件配方。

### 11.4 牵引会不会把人卡进方块

黑洞把实体往一个点拽，5 秒内**没有**做"落点是否可站立"的判定。
在复杂地形（洞穴、树叶、栅栏）里可能出现实体被压在方块里窒息的情况。
选项：不处理（原版爆炸也会这样）；或牵引时只做水平牵引、垂直只在中心上下 3 格内生效。

### 11.5 锤子要不要破盾

原版斧头命中会禁用盾牌 5 秒（`Weapon.disableBlockingForSeconds = 5.0` 就是干这个的，且是斧类默认）。
锤子在常识上**比斧头更应该破盾**，但这属于新增机制，用户没提，所以留 0.0 没做。要加的话改一个数字。

### 11.6 要不要连视觉扭曲一起施加

液态暗物质的侵蚀除了扣血，还会附加 `DARKNESS` + `BLINDNESS`。本武器**只施加了「分子离解」本身**
（因为它只描述了这一个效果），没有附赠 60 秒的致盲。
如果你觉得"被标记就该瞎掉"，说一声，加两行即可——但 60 秒致盲是很重的控制。
